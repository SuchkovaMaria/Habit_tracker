# Курсовая работа №5 и №8.Трекер привычек.

## Описание:

Данный проект разрабатывался в рамках курсовой работы и содержит следующий функционал:
1. Создание пользователя и его авторизация;
2. Создание привычки (с возможностью изменяния/удаления только авторам),
   Просмотр доступен только для своих или публичных привычек;
3. Напоминание автору привычки в телеграмм, о наступлении времени выполнения;

## Технологии:
1. Backend: Django, Django REST Framework 
2. База данных: PostgreSQL 
3. Кеш/Брокер: Redis 
4. Фоновые задачи: Celery, Celery Beat 
5. Веб-сервер: Gunicorn 
6. Контейнеризация: Docker, Docker Compose 
7. CI/CD: GitHub Actions

## Установка:

### 1 Способ - Локальная установка (без Docker)
1. Клонируйте репозиторий
   (`git clone`) [GitHub](https://github.com/SuchkovaMaria/Habit_tracker)
3. Установите зависимости
   (`pip requirements.txt`)
4. Заполните файл .env переменными согласно примеру .env.example
5. Примените миграции:
   (`python manage.py migrate`)
6. Запустите сервер:
   (`python manage.py runserver`)
7. Запустите Celery и Celery beat (в отдельных терминалах):
   (`celery -A config worker --loglevel=info -P eventlet`)
   (`celery -A config beat --scheduler django --loglevel=info`)

### 2 Способ - Запуск через Docker Compose 
1. Клонируйте репозиторий
   (`git clone`) [GitHub](https://github.com/SuchkovaMaria/Habit_tracker)
2. Заполните файл .env переменными согласно примеру указанному в .env.example
3. Запустите все сервисы 
    ```bash docker-compose up -d```
4. Дополнительные фозможности:
остановка всех сервисов
    ```docker-compose stop```;
Запуск после остановки
```docker-compose start```.

## CI/CD (Непрерывная интеграция и доставка)

Проект настроен на автоматический деплой через GitHub Actions.
При каждом пуше в ветку push и pull_request запускается процесс:

1. Автоматическое тестирование (Continuous Integration)
При создании Pull Request или пуше в ветку develop автоматически запускаются тесты:
- проверка качества кода: (опционально) линтеры и проверка стиля;
- запуск тестов: GitHub Actions запускает все тесты проекта (python manage.py test);

Статус: Если тесты падают, деплой не выполняется.
- Посмотреть статус тестов можно в разделе Actions репозитория на GitHub.
2. Автоматический деплой (Continuous Deployment)
После успешного прохождения тестов:

- Сборка Docker образа: Собирается образ с приложением. 
- Публикация в Docker Hub: Образ пушится в ваш репозиторий на Docker Hub (suchkovamaria/hw_35:latest). 
- Деплой на сервер: GitHub Actions подключается к вашему серверу:
- Копирование docker-compose.yml и конфигураций. 
- Создание .env файла с секретными переменными. 
- Скачивание свежего образа (docker-compose pull). 
- Перезапуск контейнеров (docker-compose up -d). 
- Очистка неиспользуемых образов (docker image prune -f).

3. Необходимые секреты (Secrets)
Для работы CI/CD в репозитории GitHub должны быть настроены следующие секреты (Settings → Secrets and variables → Actions):

* SERVER_IP	IP-адрес вашего сервера
* SSH_PRIVATE_KEY	Приватный SSH-ключ для подключения к серверу
* DOCKER_HUB_NAME	Имя пользователя на Docker Hub
* DOCKER_HUB_ACCESS_TOKEN	Токен доступа к Docker Hub (не пароль!)
* DJANGO_SECRET_KEY	Секретный ключ Django
* DB_NAME	Имя базы данных
* DB_USER	Пользователь базы данных
* DB_PASSWORD	Пароль базы данных
* BOT_TOKEN	Токен Telegram бота
